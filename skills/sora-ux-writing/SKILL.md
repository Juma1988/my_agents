# Sora UX Writing

Interface copy should reduce hesitation.

Prefer:
- specific action labels;
- concise plain language;
- useful error recovery;
- clear consequences;
- context before permission prompts.

Avoid:
- vague OK/Yes/No where action labels are clearer;
- blame;
- internal technical terms;
- redundant helper text;
- scary wording for normal errors.

For destructive actions:
- name the object/action;
- state consequence;
- distinguish reversible vs irreversible;
- make cancel safe and obvious.

Preserve established product voice unless Adam asks to change it.
